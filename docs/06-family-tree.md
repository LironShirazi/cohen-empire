# 06 — העץ המשפחתי 🌳

פיצ'ר עצמאי, נפרד לגמרי ממהלך המשחק. מופיע ככפתור בדף הבית לצד גלריית
התמונות, וזמין תמיד — לפני, בזמן ואחרי המירוץ.

## 1. דרישות

- כל עלה בעץ מציג: **שם + תמונה + שנת לידה** (עיגול עם תמונה או אות ראשונה)
- **שם משפחה** — שדה פר-אדם, מוצג מתחת ללב של בני הזוג. שם משותף מוצג
  פעם אחת; שני שמות שונים מוצגים שניהם (כלה שלא שינתה שם), ואם לאיש
  מהם אין שם — אין תווית
- כל משתמש יכול אחרי ההרשמה **להוסיף את עצמו** לעץ או **לערוך את העיגול שלו**
  אם הוא כבר קיים ("אני בעץ" ← בחירה עצמית או יצירת עלה חדש)
- **כפתור עריכת העץ**: במצב עריכה אפשר להוסיף לכל עלה אבא ואמא, בנים/בנות
  ובן/בת זוג, וכן למחוק עלה ללא צאצאים
- לכל עלה: **תצוגה מוגדלת** (מסך מלא: תמונה גדולה, שם, שנת לידה, טלפון,
  קרובים) או **עריכת העלה עצמו** (שם, מגדר, שנת לידה, טלפון, תמונה)
- שדה **טלפון** נערך בטופס העלה ומוצג בתצוגה המוגדלת בלבד (קישור חיוג)
- **סדר האחים לפי שנת לידה** — הבכור מימין והצעיר משמאל (העץ נקרא
  מימין לשמאל). מי שאין לו שנת לידה נדחף לקצה השמאלי, ובין חסרי שנה
  נשמר סדר ההוספה
- **ייצוא בכל רגע**: תמונה (PNG) או קובץ PDF, וגם גיבוי/ייבוא JSON
- נוח גם בסמארטפון וגם במחשב, ומתאים למשפחה גדולה ב״ה (מאות עלים)

## 2. העץ ההתחלתי

```
סבא סעדה ♥ סבתא מז׳לה        סבא חוויטה ♥ סבתא ג׳ולה
        └────────┐                 ┌────────┘
      סבא אורגני ראובן ♥ סבתא טראקי      ← "העיקר" (טבעת זהב)
                    │

```

## 3. המימוש הנוכחי — `family-tree/`

מודול ווב עצמאי ללא תלות בשרת (נפתח מכל דפדפן, כולל ישירות מהדיסק),
בעברית מלאה RTL, Mobile-First:

| קובץ | תפקיד |
|---|---|
| `index.html` | מסך העץ: סרגל כלים, קנבס SVG, כרטיס עלה, מודאלים |
| `styles.css` | עיצוב חם ומשפחתי (קרם/ירוק/זהב), Bottom Sheet במובייל |
| `js/store.js` | מודל נתונים + localStorage + העץ ההתחלתי + גיבוי/ייבוא |
| `js/layout.js` | חישוב פריסה: יחידות זוג, שיוך דורות, מרכוז ופתרון חפיפות |
| `js/render.js` | רינדור SVG + גרירה/זום (עכבר, גלגלת, צביטה במובייל) |
| `js/ui.js` | כרטיס עלה, תצוגה מוגדלת, טפסים, "אני בעץ", חיפוש |
| `js/export.js` | ייצוא PNG/PDF (ללא ספריות — כולל בניית PDF ידנית) |

### מודל הנתונים (אדם)

```js
{ id, name, lastName, gender, birthYear, phone, photo /* URL */,
  fatherId, motherId, partnerId, isRoot, sortOrder }
```

- **זוגיות** מוסקת משני מקורות: `partnerId` מפורש + הורות משותפת של ילd
- **אלגוריתם הפריסה**: בני זוג מאוחדים ל"יחידות" (union-find); כל יחידה
  משויכת לדור (מסלול ארוך ביותר מהשורשים); סדר ראשוני בסריקת עומק ששומרת
  אחים יחד; ואז איטרציות מרכוז דו-כיווניות (ילדים מתחת להורים ↔ הורים מעל
  הילדים) עם פתרון חפיפות בשיטת צברים ששומר על מרכוז. סקלאבילי למאות עלים.
- **ייצוא PDF**: העץ מרונדר ל-SVG עצמאי ← Canvas ← JPEG ← קובץ PDF מינימלי
  שנבנה ידנית (עמוד יחיד עם התמונה, `DCTDecode`) — בלי אף ספריה חיצונית.

**מאז שלב 3 הקבצים חיים תחת `web/`:** המנוע ב-`web/public/family-tree/js/`,
והמעטפת (HTML + CSS) בראוט `web/app/family-tree/`. `index.html` ו-`styles.css`
העצמאיים נמחקו — העץ כבר לא נפתח מהדיסק, כי הוא צריך session ו-Supabase.

## 4. האינטגרציה עם האפליקציה (Supabase) — מומש בשלב 3

### טבלת `family_members`

| שדה | סוג | הערות |
|---|---|---|
| id | uuid PK | |
| profile_id | uuid FK → profiles, nullable | קישור "זה אני" של משתמש רשום |
| name | text | |
| gender | text | `m` / `f` / null |
| birth_year | int | |
| phone | text | מוצג בתצוגה המוגדלת בלבד |
| photo_url | text | Supabase Storage (bucket `family-tree`) |
| father_id, mother_id | uuid FK self | |
| partner_id | uuid FK self | |
| is_root | bool | סבא אורגני וסבתא טראקי |
| sort_order | int | סדר אחים |
| created_by, updated_at | | מעקב |

הטבלה נוצרה כבר ב-`0001`; `0010_phase3_family_tree.sql` פתחה אותה לכתיבה
והוסיפה `created_by`, `updated_at`, ייחודיות ל-`profile_id`, את ה-bucket
ואת העץ ההתחלתי.

### מדיניות RLS

- **קריאה:** כל משתמש מחובר (העץ שייך לכולם)
- **כתיבה:** כל משתמש מחובר מוסיף ועורך **כל עלה** — שם, תמונה, קשרים.
  זו החלטה מודעת: `addPartner`/`addParents` מעדכנות את השורה הקיימת, ולכן
  נעילת עלה תפוס הייתה חוסמת בשקט בדיוק את העריכות הנפוצות ביותר (דוד
  שמוסיף בת זוג לאחיין שכבר סימן "זה אני")
- **"זה אני" (`profile_id`) הוא השדה היחיד שמוגן:** מותר לתפוס עלה פנוי
  לעצמי ולשחרר את שלי; אסור לקחת עלה של אחר או לשייך עלה למשתמש אחר.
  לא ניתן לביטוי במדיניות (RLS לא רואה את הערך הישן) ולכן זה הטריגר
  `guard_family_member_identity`. מנהל-על עוקף.
- **מחיקה:** `father_id`/`mother_id` הם `on delete restrict`, כלומר
  Postgres עצמו מסרב למחוק עלה עם צאצאים. זו הגנה אטומית, בניגוד לבדיקת
  "אין ילדים" במדיניות שהייתה נכונה רק עד ה-INSERT הבא. הקליינט מתרגם 23503.

### המתאם (`js/store.js`)

אותו API בדיוק (`get/all/childrenOf/...`), ולכן `layout.js`, `render.js`
ו-`ui.js` **לא השתנו** במעבר ל-Supabase (ב-`ui.js` נגענו רק אחר-כך, בשדה
התמונה — ראו למטה). הקריאות חייבות להישאר סינכרוניות (`render.draw()`
קורא ל-`all()` בתוך הרינדור), ולכן:

1. `load()` טוען הכל פעם אחת למפה בזיכרון ונרשם ל-Realtime
2. קריאות מוגשות מהמפה, סינכרונית
3. כתיבה אופטימית: מעדכנים את המפה, מציירים מיד, ובמקביל שולחים לשרת
   diff מול תמונת המצב האחרונה. כישלון → הודעה + טעינה מחדש
4. הוספות נשלחות **בלי `partner_id`** ובסדר הורים-לפני-ילדים, כי FK נבדק
   לכל שורה בנפרד וזוגיות היא מעגלית (א↔ב); ה-`partner_id` נסגר בעדכון שאחריו

### שדה התמונה ומיקומה בעיגול (`js/ui.js`)

בורר הקבצים הנייטיבי היה יעד מגע זעיר בנייד ("לא נבחר קובץ"), ולכן
ה-`input[type=file]` מוסתר ומופעל דרך שני יעדים גדולים: **העיגול עצמו**
וכפתור "בחירת תמונה" לצידו.

אחרי הבחירה נפתח מסך **מיקום בעיגול** (`openCropper`): קנבס מרובע עם
טבעת מכהה, גרירה באצבע אחת, צביטה בשתיים, וגם סליידר זום — כי בדסקטופ
ובנגישות אין צביטה. מצב החיתוך נשמר כשברים מצלע הריבוע (`scale/ox/oy`),
ולכן אותו חישוב משרת גם את התצוגה על המסך וגם את הפלט.

**מה שנשמר הוא הריבוע החתוך עצמו**, JPEG של עד 512px — ולכן `render.js`
(שמצייר `<image preserveAspectRatio="…slice">`), `export.js` וה-CSS
(`object-fit: cover`) לא צריכים לדעת על החיתוך כלום, ובטבלה לא נוסף שדה.
המחיר: מיקום מחדש של תמונה שכבר עלתה ל-bucket טוען אותה מחדש
(`crossOrigin="anonymous"`, ה-bucket ציבורי) ומקודד אותה שוב.

### התאמת העיצוב למערכת העיצוב (`family-tree.css`)

העץ נבנה כעמוד עצמאי, ולכן הייתה לו פלטה משלו — ירוק-יער `#23422F`
וקרם `#F7F1E6`, `--radius: 14px` ופונטי מערכת. אף אחד מהם לא קיים
במערכת העיצוב, וגרוע מזה: הוא הגדיר `--ink`, `--line`, `--gold`,
`--danger`, `--radius` ו-`--shadow` — שמות שכבר קיימים ב-`globals.css`.

**מה השתנה — ה-chrome בלבד:**

| היה | הפך ל | מקור |
|---|---|---|
| ירוק-יער בכותרת | הרקע הקוסמי (`.cosmic`) עם כותרת בזהב | `globals.css` |
| ירוק בכפתור הראשי ובמצב עריכה פעיל | `--brand` עם הצל הקשיח של `Button` | `components/ui/button.tsx` |
| פונטי מערכת | Rubik לגוף, Secular One לכותרות | `layout.tsx` |
| `--radius: 14px` | `--radius-card` / `--radius-card-sm` (18/12) | `globals.css` |
| קרם `#F7F1E6` | `--bg` / `--bg-2` | `globals.css` |
| טוסט ירוק | נאבי עם זהב (`.chip-navy`) | `design-system/styles.css` |
| שדות 15px, מסגרת 1.5px | 16px ומסגרת 2px עם טבעת `--brand-soft` | `components/ui/field.tsx` |

**מה נשמר בכוונה:** פלטת הצמתים ב-SVG (`--ft-*`) — טבעת זהב לשורש
וטבעות לפי מגדר נושאות משמעות (§2), ואדום/צהוב המירוץ היו נלחמים
בתמונות. הירוק היחיד ששרד הוא סימון "זה אני", ואף הוא הועבר ל-`--ok`
של מערכת העיצוב.

**16px בשדות זו החלטה ולא טעם:** ספארי בנייד מזנק זום על שדה שהטקסט בו
קטן מ-16px, וזה שבר את הפריסה בכל פתיחת טופס.

⚠️ **`js/export.js` משכפל את פלטת הצמתים ואת רקע הקנבס כ-hex קשיח**, כי
ה-SVG המיוצא חייב להיות עצמאי מה-CSS של הדף. כל שינוי צבע כאן חייב לגעת
גם שם. הפונטים הם היוצא מן הכלל: הייצוא נשאר על מחסנית מערכת ולא על
Rubik, כי SVG שנטען כ-`<img>` לא מושך פונטי ווב.

### מה שנשאר פתוח

- **קבצים יתומים ב-bucket:** החלפת תמונה משאירה את הקודמת. אותו חוב שכבר
  קיים ב-`chat-files` ובתחנות — צריך החלטת שימור, לא תיקון נקודתי.
- **ייבוא JSON מוגבל למנהל-על:** העץ כבר לא פרטי לדפדפן, וייבוא דורס את
  מה שכל המשפחה הזינה. "איפוס לעץ ההתחלתי" הפך להודעה בלבד.
